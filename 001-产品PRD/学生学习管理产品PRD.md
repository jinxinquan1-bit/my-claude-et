## 2. 产品概述

### 2.1 背景与问题

家教/培训老师每天要给多名学生上课，学生的学习情况（上课内容、作业、课堂表现、知识点掌握）通常散落在：

- 微信聊天记录里（难回看、难汇总）
- 纸质笔记本 / Excel 里（记录成本高、容易中断）
- 脑子里（过几天就忘）

由此产生三个核心痛点：

1. **记录零散**：没有统一的地方沉淀，无法形成长期跟踪；
2. **反馈不及时**：家长了解孩子情况依赖老师的口头/微信碎片化反馈，信息不完整；
3. **无数据沉淀**：老师无法看到学生一个月、一学期的进步趋势，续费沟通也缺少依据。

### 2.2 产品定位

一款面向家教/培训老师的**轻量级学生每日学习记录与成长档案工具**：

> **30 秒完成一次记录 → 自动沉淀为每个学生的成长档案 → 一键生成学习报告分享给家长。**

### 2.3 目标用户

| 用户 | 角色 | 说明 |
| --- | --- | --- |
| 家教老师 / 小型机构老师 | 核心用户 | 管理 1~30 名学生，每天记录学生学习情况 |
| 学生家长 | 间接用户（只读） | 通过分享链接查看孩子的学习报告，**无需注册登录** |

### 2.4 产品目标（第一版）

| 指标 | 目标值 |
| --- | --- |
| 单次学习记录耗时 | ≤ 60 秒（不含照片上传） |
| 记录留存 | 每名学生都有连续、可回看的学习档案 |
| 家长触达 | 老师每周可为 ≥ 80% 的在读学生生成并分享报告 |
| 活跃度 | 上线 4 周后，老师周活跃天数 ≥ 5 天 |

### 2.5 产品原则

- **记录优先**：一切设计围绕"降低每日记录成本"，宁可功能少，不可记录慢；
- **手机优先**：第一版只做 Web，但按手机浏览器（含微信内置浏览器）体验来设计，桌面端保证可用即可；
- **数据属于老师**：老师的数据可随时导出（P1），学生档案是核心资产；
- **严格控制范围**：不做排课、收费、题库等教务系统功能。

## 3. 核心使用场景

### 场景 1：下课后 30 秒记录（高频，每天多次）

> 王老师刚给小明上完一节数学课，走出教室，掏出手机打开网页 → 首页显示"待记录：小明（数学）" → 点进去，日期和科目已默认填好 → 勾选作业"已完成"、点 3 颗星、选知识点"一元二次方程 → 基本掌握" → 补一句备注"应用题还需练习" → 保存。全程 30 秒。

### 场景 2：周末向家长汇报（每周一次）

> 周五晚上，王老师打开小明的学生档案 → 点击"生成学习报告" → 选择"本周" → 自动生成报告（上课 3 次、作业完成率 100%、专注度趋势上升、老师寄语）→ 生成分享链接 → 微信发给小明妈妈 → 妈妈点开链接直接看到报告，无需安装、无需登录。

### 场景 3：回看长期进步（每月/续费时）

> 月底，王老师回看小明的档案时间线："刚来时解方程正确率很低，这个月明显进步" → 用趋势统计截图发给家长，支撑续费沟通。

## 4. 功能需求

### 4.0 功能总览

```
学迹 V1.0
├── 账号（老师注册/登录）
├── 学生管理
│   ├── 添加 / 编辑 / 删除 / 搜索学生
│   └── 学生状态（在读 / 停课 / 结课）
├── 每日学习记录（核心）
│   ├── 快速记录（30 秒原则）
│   ├── 记录列表 / 时间线
│   └── 记录编辑 / 删除
├── 统计
│   ├── 学生维度（次数、作业完成率、表现趋势、知识点掌握）
│   └── 全局维度（今日待记录、本周记录量）
└── 学习报告与家长分享
    ├── 报告生成（本周 / 本月 / 自定义范围）
    ├── 分享链接（免登录查看、有效期、可撤销）
    └── 家长端报告页（只读 H5）
```

### 4.1 账号与登录

| 编号 | 需求 | 说明 | 优先级 |
| --- | --- | --- | --- |
| A-1 | 老师注册 | 手机号 + 验证码（或密码）注册 | P0 |
| A-2 | 老师登录 | 手机号 + 密码/验证码登录，登录态保持 30 天 | P0 |
| A-3 | 找回密码 | 手机验证码重置 | P1 |
| A-4 | 家长免登录 | 家长通过分享链接查看报告，**不注册、不登录** | P0 |

> 第一版为单老师个人使用，不做多老师协作、不做机构账号。

### 4.2 学生管理

| 编号 | 需求 | 说明 | 优先级 |
| --- | --- | --- | --- |
| S-1 | 添加学生 | 字段见下方数据模型；仅**姓名必填**，其余选填，10 秒可完成添加 | P0 |
| S-2 | 学生列表 | 默认按"最近记录时间"排序；支持按姓名搜索；显示在读状态 | P0 |
| S-3 | 编辑学生 | 全部字段可改 | P0 |
| S-4 | 删除学生 | 软删除 + 二次确认；删除后档案可恢复（30 天） | P0 |
| S-5 | 学生状态 | 在读 / 停课 / 结课；停课学生置灰但仍可查看档案 | P0 |
| S-6 | 批量导入 | Excel 模板导入学生名单 | P1 |
| S-7 | 学生标签 | 自定义标签（如"冲刺中考""基础薄弱"），支持筛选 | P1 |

**添加学生字段**：姓名（必填）、称呼/昵称、年级、学校、默认科目、课程安排（可选）、头像、备注。

### 4.3 每日学习记录（核心功能）

#### 4.3.1 记录字段

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| 日期 | 日期 | 是 | 默认今天，可改为历史日期 |
| 科目 | 单选 | 否 | 默认取学生的默认科目 |
| 学习内容 | 文本 | 否 | 本次课学了什么；支持从该生历史记录一键带入 |
| 作业完成情况 | 单选 | 否 | 已完成 / 部分完成 / 未完成 / 本次无作业 |
| 作业描述 | 文本 | 否 | 如"练习册 P32~P35" |
| 专注度 | 星级 | 否 | 1~5 星，默认 3 星 |
| 状态标签 | 多选 | 否 | 预设：状态很好 / 状态一般 / 注意力不集中 / 情绪低落 / 进步明显 / 需要鼓励；支持自定义 |
| 知识点与掌握度 | 组合 | 否 | 知识点文本 + 掌握程度（未掌握/初步掌握/基本掌握/熟练掌握） |
| 老师评语 | 文本 | 否 | 一句话点评，会展示给家长 |
| 照片 | 图片 | 否 | 作业/课堂照片，最多 4 张 | P1 |

#### 4.3.2 交互要求（30 秒原则）

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| R-1 | 入口 | 首页"今日待记录"卡片 + 学生详情页"记一笔"按钮 |
| R-2 | 默认值友好 | 日期=今天、科目=默认科目、专注度=3 星，减少点击 |
| R-3 | 复制上次 | "按上次记录填充"按钮，一键带入该生上次的内容/标签/知识点 |
| R-4 | 快速保存 | 所有字段选填，最小可只选日期直接保存；保存后提示成功并可"继续记录下一位学生" |
| R-5 | 编辑/删除 | 记录可修改、可删除（二次确认） |
| R-6 | 历史补记 | 支持选择过去日期补记 |
| R-7 | 输入法适配 | 文本输入在移动端浏览器中放大字体、避免遮挡 |

#### 4.3.3 学生档案（时间线）

- 学生详情页按时间倒序展示全部记录，每条记录卡片展示：日期、科目、核心内容、作业状态、专注度星级、标签、评语；
- 顶部固定展示学生信息 + 快捷统计卡（本月上课 N 次 / 作业完成率 / 平均专注度）。

### 4.4 统计

| 编号 | 需求 | 说明 | 优先级 |
| --- | --- | --- | --- |
| T-1 | 学生维度统计 | 上课次数、作业完成率、专注度趋势折线、知识点掌握分布 | P0 |
| T-2 | 全局概览 | 今日待记录名单、近 7 天记录量 | P0 |
| T-3 | 时间范围筛选 | 本周 / 本月 / 自定义 | P1 |
| T-4 | 统计图表 | 轻量图表（趋势折线、完成率环图），移动端可读 | P0 |

### 4.5 学习报告与家长分享

| 编号 | 需求 | 说明 | 优先级 |
| --- | --- | --- | --- |
| P-1 | 生成报告 | 选择学生 + 时间范围（本周/本月/自定义）→ 自动生成报告 | P0 |
| P-2 | 报告内容 | ① 学习概览（上课次数、涉及科目）② 作业完成统计 ③ 专注度趋势 ④ 知识点掌握列表 ⑤ 老师寄语（可选，可编辑） | P0 |

## 6. 视觉设计规范（配色方案）

### 6.1 设计基调

**蓝色为主、简约克制**：以品牌蓝作为唯一主色，大面积留白 + 浅色背景；颜色只用来表达「状态」和「操作」，不做装饰。整体气质：清爽、专业、可信赖。

### 6.2 主色（品牌蓝）

| 色阶 | 色值 | 用途 |
| --- | --- | --- |
| 品牌蓝（Primary） | `#3B82F6` | 主操作按钮、选中态、链接、关键数据 |
| 深蓝（Hover/Active） | `#2563EB` | 按钮按压态、悬停态 |
| 强调深蓝（Deep） | `#1E40AF` | 大数字、图表强调、熟练掌握标记 |
| 浅蓝（Light） | `#EFF6FF` | 选中背景、浅色卡片底、标签底 |
| 蓝描边（Border） | `#BFDBFE` | 浅蓝描边、选中描边 |

### 6.3 中性色（文字与背景）

| 色阶 | 色值 | 用途 |
| --- | --- | --- |
| 标题文字 | `#111827` | 页面标题、学生姓名 |
| 正文文字 | `#374151` | 记录内容、正文 |
| 次要文字 | `#6B7280` | 时间、辅助说明 |
| 占位/禁用 | `#9CA3AF` | 输入框占位、禁用态 |
| 边框/分割线 | `#E5E7EB` | 卡片描边、列表分割 |
| 页面背景 | `#F5F7FA` | 全局背景（微带蓝调的浅灰） |
| 卡片背景 | `#FFFFFF` | 卡片、表单、弹窗 |

### 6.4 功能色（语义色，仅用于状态表达）

| 语义 | 色值 | 浅底 | 用途 |
| --- | --- | --- | --- |
| 成功 | `#22C55E` | `#F0FDF4` | 作业已完成、「状态很好」标签 |
| 警告 | `#F59E0B` | `#FFFBEB` | 作业部分完成、「需要鼓励」标签 |
| 危险 | `#EF4444` | `#FEF2F2` | 作业未完成、删除操作 |
| 中性 | `#64748B` | `#F1F5F9` | 「情绪低落」等中性状态标签 |

> **图表标记色（经色盲/对比度校验加深）**：已完成 `#15803D`、部分完成 `#F59E0B`、未完成 `#EF4444`；徽章文字同步加深为 `#15803D` / `#B45309` / `#DC2626`（保证浅底上的可读性）。

### 6.5 数据与状态色映射

| 场景 | 配色规则 |
| --- | --- |
| 知识点掌握程度 | 蓝色渐进：未掌握 `#60A5FA` → 初步掌握 `#3B82F6` → 基本掌握 `#2563EB` → 熟练掌握 `#1E40AF`（单色相、明度单调渐深，经色盲/对比度校验调整） |
| 专注度星级 | 点亮星填充主蓝 `#3B82F6`，未点亮用 `#E5E7EB` |
| 状态标签 | 按 6.4 语义色映射，浅底 + 深字 |
| 统计图表 | 默认单色蓝 `#3B82F6`；多序列时用蓝色渐阶（`#60A5FA` → `#1E40AF`），必要时引入成功绿作对比色 |

### 6.6 使用原则（简约约束）

1. 每屏最多 **1 个**实心蓝主按钮，其余操作使用线框/文字按钮；
2. 蓝色只出现在：主操作、选中态、链接、关键数据；
3. 大面积留白：卡片间距 ≥ 16px，圆角统一 12px；
4. 文字层级靠中性色深浅区分，不用颜色区分正文；
5. 功能色仅用于状态表达，禁止用于装饰；
6. 图标统一线性风格（stroke），颜色跟随文字；
7. 颜色统一以设计 Token（CSS 变量）管理，便于后续小程序/App 复用。

## 7. 数据模型（核心表）

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| users | id, phone, password_hash, nickname, created_at | 老师账号 |
| students | id, user_id, name, nickname, grade, school, default_subject, schedule, avatar, status(在读/停课/结课), remark, deleted_at, created_at, updated_at | 学生档案 |
| learning_records | id, student_id, user_id, record_date, subject, content, homework_status, homework_desc, focus(1-5), tags(json), knowledge_point, mastery_level, comment, photos(json), created_at, updated_at | 每日学习记录（核心表） |
| reports | id, student_id, user_id, period_start, period_end, content_snapshot(json), teacher_message, created_at | 报告（数据快照，防止记录修改影响已发报告） |
| share_tokens | id, report_id, token(随机长字符串), expires_at, revoked(bool), created_at | 分享链接与权限 |

**要点**：
- 记录表冗余存 `student_id` 与 `user_id`，方便按老师/学生双维度查询；
- 报告采用**快照机制**：生成时固化数据，之后修改原始记录不影响已发出的报告；
- `share_tokens.token` 使用高熵随机串，不可枚举，保证家长数据隐私。

## 8. 非功能需求

| 类别 | 需求 |
| --- | --- |
| 兼容性 | 移动端优先：微信内置浏览器、iOS Safari、Android Chrome 必须完全可用；桌面浏览器保证可用 |
| 性能 | 4G 网络下首屏 ≤ 3 秒；记录保存即时反馈（乐观更新，失败可重试） |
| 安全 | 全站 HTTPS；密码加密存储；分享 token 不可枚举、可撤销、可过期 |
| 隐私 | 学生数据仅老师本人可见；家长仅能通过有效链接看到对应学生报告 |
| 数据 | 服务端自动备份；老师可导出学生数据（P1） |
| 可用性 | 弱网/断网时表单填写内容不丢失（自动暂存草稿） |
| 技术选型建议 | 前端 React/Vue 移动端适配即可；后端任意（Node/Python/Java）；数据库 MySQL/PostgreSQL；部署单机即可（小产品）；配色以设计 Token（CSS 变量）管理（见第 6 章）——**建议，非约束** |

## 9. 版本规划

### V1.0（MVP，本次目标）

账号登录、学生管理、每日学习记录、档案时间线、基础统计、报告生成 + 链接分享。

### V1.1（迭代）

照片上传、记录提醒（今日漏记推送）、学生标签、Excel 导入导出、报告长图/PDF 导出、自定义状态标签管理。

### V2.0（远期）

微信小程序 / 移动端 App、家长互动（留言/回复）、多老师协作、进阶数据洞察（周报自动生成）。

### 明确不做

排课教务系统、收费管理、题库/组卷、在线课堂。

## 10. 验收标准（核心用例）

1. 新老师 3 分钟内完成注册、添加第一名学生；
2. 老师从首页进入"记一笔"到保存成功，全程 ≤ 60 秒（不含照片）；
3. 学生详情页可完整回看历史记录，按时间倒序；
4. 老师可生成一周学习报告，复制链接在微信内打开，家长免登录即可查看；
5. 老师撤销链接后，该链接立即失效；
6. 修改历史记录后，已生成的报告内容不受影响（快照机制）；
7. 弱网下保存失败有明确提示，且已填内容不丢失。

## 11. 风险与开放问题

### 风险

| 风险 | 应对 |
| --- | --- |
| 老师坚持不下来（记录负担） | 30 秒记录原则 + 首页待记录提醒 + 记录默认值，把摩擦降到最低 |
| 微信对 H5 链接的分享限制 | 引导"复制链接"发送，不依赖微信分享卡片 |
| 家长数据隐私泄露 | 随机 token + 有效期 + 可撤销 + 报告快照 |
| 单人/小团队开发，范围膨胀 | 严格执行 MVP 边界，V1.0 砍掉一切非核心功能 |

### 开放问题（待确认）

1. 是否需要支持多位老师共用（小型机构场景）？——V1.0 假定单老师单账号；
2. 学生名单是否需要 Excel 批量导入？——V1.0 手工添加，量大再加；
3. 报告是否需要在生成时向老师推送确认？（防误发）——V1.0 默认老师主动生成后自行发送。

## 附录：V1.0 最小可用闭环

```
添加学生 → 每天"记一笔"（30秒） → 档案时间线沉淀
                    ↓
              生成周/月报告 → 分享链接 → 家长微信打开查看
                    ↓
              老师看统计趋势 → 续费/沟通有依据
```
